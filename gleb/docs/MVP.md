# MVP: как запустить и проверить

Состояние на 2026-10-24. Что проверено, а что нет, перечислено в конце. Ничего из списка «не проверено» не нужно считать работающим.

## Что внутри

| Сервис | Язык | Что делает в MVP |
|---|---|---|
| `caddy` | — | TLS наружу (`https://localhost:8443`), CSP и прочие заголовки, раздача SPA, mTLS к gateway и Keycloak |
| `gateway` | Rust | BFF: вход через Keycloak (code + PKCE), сессия в NATS KV (AES-GCM), токены в браузер не попадают, прокси `/api/v1/*` по mTLS, SSE |
| `keycloak` | — | пользователи, организации = тенанты, роли, token exchange, X.509-аутентификация сервисов |
| `tenancy` | Rust | настройки организации (режим налогообложения, «сегодня», лимиты, политика LLM), заведение организаций и владельцев в Keycloak |
| `ingest` | Rust | CSV в формате датасета и 1CClientBankExchange, дедупликация, проверка непрерывности остатка, outbox |
| `categorizer` | Python | правила из `rules/categories.yaml` (99,7% операций датасета), дообучаемая модель на хвост, спасательные поступления, даты документов, режим налогообложения |
| `obligations` | Rust | будущие платежи (ручные, счета, налоговый календарь), план-факт, сводное предупреждение о просрочках |
| `forecast` | Python | прогноз по слоям + Монте-Карло, разрывы с причинами, сценарии, план-факт, бэктест по истории тенанта |
| `alerts` | Rust | предупреждения о разрывах и просрочках, схлопывание повторов |
| `advisor` | Python 3.14 | консультант на облачной модели через Hermes Agent; без провайдера отвечает шаблоном из прогноза |
| `advisor-tools` | Rust | MCP-сервер с 8 инструментами, token exchange в Keycloak, предложения вместо записи |
| `llm-gateway` | Rust | единый выход к облачным моделям: Claude, OpenAI, Gemini, OpenRouter; маскирование, бюджеты, аудит |
| `connectors` | Python | replay датасета (выписка + «выставленные счета»), синтетический реестр контрагентов, seed демо-тенантов |
| `step-ca` + `cert-*` | — | внутренний CA, сертификат с SPIFFE ID на каждый сервис, автопродление |
| `postgres`, `nats` | — | вход только по клиентскому сертификату, без паролей; у NATS права на субъекты для каждого сервиса |

## Запуск на ноутбуке (Linux, Docker)

```bash
git clone https://github.com/swimshadow/CenterInvestDGTUHack2026.git && cd CenterInvestDGTUHack2026
git checkout tested
# датасет организаторов распаковать в data/ (в git его нет)
make secrets     # deploy/dev-secrets/, печатает пароль демо-пользователей
make up          # первая сборка образов 15–25 минут, дальше ~2 минуты
make seed        # четыре демо-тенанта из датасета, около минуты
```

Откройте `https://localhost:8443` и примите сертификат локального CA Caddy. Вход:

| Логин | Компания | «Сегодня» | Что показать |
|---|---|---|---|
| `owner@demo-a.ci1.local` | C084, продуктовый магазин | 24.12.2025 | разрыв около 22.01 (в данных владелец закрыл минус 21.01) |
| `owner@demo-b.ci1.local` | C117, растениеводство | 24.10.2025 | разрыв около 07.11 (в данных — 14.11) |
| `owner@demo-c.ci1.local` | C061, детский центр | 04.07.2025 | разрыв около 27.07 (в данных — 01.08) |
| `owner@demo-d.ci1.local` | C110, база отдыха | 16.09.2026 | короткая история, плашка «мало данных» |

Пароль: `cat deploy/dev-secrets/demo_password`. Вход двухшаговый (сначала логин, потом пароль): так Keycloak работает при включённых организациях.

Если нужен доступ с другой машины, задайте `PUBLIC_URL=https://<ip>:8443` перед `make up`. На него настроены redirect URI в Keycloak и issuer токенов.

Нужно около 3 ГБ свободной памяти. Keycloak с Postgres берут примерно 1 ГБ.

### Консультант и облачные модели

Консультант работает только на облачных моделях, локальной модели и GPU нет. Ключи провайдеров лежат в `deploy/dev-secrets/`: `anthropic_api_key`, `openai_api_key`, `gemini_api_key`, `openrouter_api_key`. `make secrets` создаёт их пустыми. Заполните нужные и перезапустите `llm-gateway`. Владелец выбирает провайдера в «Настройках» и разрешает отправку обезличенных данных.

- **Провайдер выбран и доступен.** Отвечает Hermes Agent, при его сбое — встроенный цикл на той же модели.
- **Провайдер не подключён.** Консультант отвечает шаблоном: дата и сумма ближайшего разрыва, причины и три действия. Над ответом плашка «подключите ИИ-провайдера», владельцу показана ссылка на настройки.
- **Провайдер недоступен.** Ответ тот же, по шаблону, с плашкой «провайдер сейчас недоступен».

## Что проверить руками

1. **Главная.** Фраза про ближайший разрыв, график с коридором P10–P90, разрывы с причинами, предупреждения.
2. **«Прошла неделя»** (демо-плашка). Подаются операции следующей недели через обычный ingest, прогноз пересчитывается за секунды (на главной видно «расчёт N мс»), появляется план-факт.
3. **Операции.** Смена категории применяется ко всем операциям контрагента.
4. **Будущие платежи.** Ручное событие сразу попадает в прогноз. Счета из «ЭДО (реконструкция)» сами закрываются оплатами.
5. **Что если.** Четыре сценария из кейса, два графика.
6. **Консультант.** Вопрос → ответ с цифрами из инструментов → карточка «Добавить» для предложений.
7. **Качество прогноза.** Бэктест на истории тенанта, сравнение пяти подходов (до минуты на первом открытии).
8. **Настройки.** Подтверждение режима налогообложения включает налоговый календарь, лимит овердрафта даёт второй уровень предупреждений.
9. **Изоляция.** Войдите вторым пользователем в другом окне: данные не пересекаются.

## Автоматические проверки

```bash
make test    # Rust: 38 тестов (nextest), Python: 24 теста
make lint    # fmt, clippy -D warnings, ruff, генерация deploy-файлов в синхроне
make e2e     # 15 сценариев против поднятого стенда
make backtest  # бэктест на реальном датасете (30 компаний), отчёт в ml/reports/
```

Что делает `make e2e`:

- настоящий вход через Keycloak;
- 401 без сессии, заголовки безопасности, отсутствие JWT в ответах браузеру;
- изоляция тенантов, CSRF;
- запрет внешнего провайдера без маскирования;
- отказ четырёх внутренних сервисов в соединении без клиентского сертификата (проверяется изнутри сети `ci1_app`);
- сценарий, консультант, replay с план-фактом;
- log-canary: назначение и имя контрагента с маркером не попадают в журналы ни одного контейнера.

## Качество прогноза (бэктест на датасете)

`make backtest`: 30 компаний, 211 срезов, горизонт 30 дней, 35 окон с реальными разрывами. Разрыв — это минус на счёте или спасательное поступление собственных денег.

| Подход | Ошибка, дней оборота | Коридор P10–P90 | Точность разрывов | Полнота | Заблаговременность |
|---|---|---|---|---|---|
| остаток не меняется | 2,35 | 0,5% | — | 0% | — |
| бутстреп по дням недели | 2,53 | 80% | 41% | 80% | 15 дней |
| слои (регулярные + остаток) | 2,57 | 75% | 47% | 80% | 14,5 дня |
| слои + выставленные счета | 2,79 | 70% | 46% | 80% | 12,5 дня |
| повтор прошлой недели | 5,58 | 0% | 36% | 57% | 15 дней |

Как это читать честно:

- По средней ошибке остатка плоская наивная модель пока точнее. Но она не видит ни одного разрыва.
- Наши варианты ловят 80% разрывов в среднем за две недели до события, а коридор P10–P90 у бутстрепа откалиброван (80%).
- Слой выставленных счетов на реальных данных пока ухудшает ошибку. На синтетике он лучший (3,09 против 3,78), то есть механизм работает, а настройка под реальные данные — задача ML-команды.
- Модели — базовые реализации за интерфейсом `Forecaster`. Новые подключаются в `services/forecast/src/forecast/models.py` и сразу появляются в бэктесте.

## Что проверено и что нет

**Проверено** на сервере (Ubuntu 24.04, 4 ГБ RAM) и на ноутбуке pop-os (12 ядер, 14 ГБ), где сейчас работает стенд:

- `make up` с нуля, `make seed`, все сервисы `healthy`;
- 15 из 15 e2e-сценариев;
- все unit-тесты;
- clippy с `-D warnings`, `cargo fmt`, ruff;
- `cargo deny` (advisories, лицензии, bans, sources);
- hadolint, actionlint, shellcheck;
- ansible-lint (профиль production) и `--syntax-check`;
- конвертация 57 Quadlet-юнитов генератором Podman 4.9 (dry-run);
- скриншоты основных экранов через Playwright;
- CI на раннерах GitHub: rust, python (с гейтом качества на синтетике), web, security;
- сборка, подпись cosign и скан trivy всех 12 образов при попадании в `tested` (0 HIGH/CRITICAL).

**Не проверено:**

- облачные провайдеры: ключей здесь нет, вызывались только адаптеры в unit-тестах;
- полный диалог через Hermes. Проверено, что Hermes стартует с нашим конфигом и регистрирует все 8 MCP-инструментов через loopback-прокси. Ответ модели через Hermes не проверен: ему нужна облачная модель, а ключей здесь нет. Ответ по шаблону без провайдера покрыт e2e;
- pull-деплой агентом. Агент описан в Ansible-роли, но в `stable` ещё не было релиза;
- Ansible-роли против живого ноутбука, Quadlet-юниты в работе под systemd;
- продление сертификатов. Срок 7 дней, продление на 2/3 срока: перечитывание в сервисах написано, но реальный цикл продления не наблюдался;
- e2e не встроен в CI, гоняется локально.

## Отличия от ARCHITECTURE.md

- **mTLS для агента.** Вместо sidecar ghostunnel используется loopback-прокси внутри контейнера advisor: Hermes ходит на 127.0.0.1, прокси добавляет сертификат, токен пользователя и тенанта.
- **Перечитывание сертификатов.** Python-сервисы перечитывают сертификат на лету через `SSLContext.load_cert_chain` и не перезапускаются. Postgres, NATS и Caddy перечитывают его по сигналу.
- **Инструменты MCP.** `initialize` и `tools/list` отвечают без пользователя: агент узнаёт инструменты при старте, а соединение по-прежнему только mTLS от `advisor`. `tools/call` требует токен пользователя.
- **Токены сервисов не привязаны к сертификату** (RFC 8705): сервисы не проверяют `cnf`, поэтому включать привязку было бы декорацией.
- **Секреты в dev** лежат файлами в `deploy/dev-secrets/` с правами 0644. В режиме без swarm Docker не умеет задавать владельца секрета. На стенде используются Podman secrets с uid сервиса.
- **cert-agent получает пароль провайдера step-ca**, то есть может выпустить сертификат на любое имя. Сервисные контейнеры пароля не видят. В плане — одноразовые токены выпуска из Ansible вместо пароля.
- **step-ca пишет в журнал одноразовые токены выпуска** (живут 5 минут, одноразовые). Стоит понизить уровень журнала.
- **Налоговый календарь** упрощён: ЕНП 28-го плюс пики по режиму. Правила должен проверить человек, который разбирается в налогах.
- **Производственный календарь** для будущих дат упрощён: выходные и фиксированные праздники.
