# Внешний API по токену

Внешние системы (1С, BI, скрипты) обращаются к данным компании с токеном. **Идентификатор компании не нужен**: токен привязан к пользователю, а значит к его единственной компании, поэтому в путях `/api/ext/v1/*` её id нет.

## Токены
Создаются и отзываются в «Настройки → Доступ по API» (или `GET|POST /api/v1/account/tokens`, `DELETE /api/v1/account/tokens/{id}` под cookie-сессией).
- Формат `ckt_<43 символа>`; показывается один раз при создании, в БД `auth.db` хранится только sha256.
- До 10 токенов на пользователя; для каждого видны название, префикс, дата создания и последнего использования.
- Токен не даёт доступа к аккаунту: управлять способами входа и токенами можно только по сессии.

## Запросы
`Authorization: Bearer ckt_…`, ответы в том же формате, что у публичного API (суммы — копейки строками).

| Метод и путь | Что делает |
|---|---|
| `GET /api/ext/v1/company` | название, ИНН, ОГРН |
| `GET /api/ext/v1/forecast` | последний базовый прогноз (пересчитывается сам, если данные изменились) |
| `POST /api/ext/v1/forecast` `{"horizon_days": 7..90}` | построить прогноз |
| `GET /api/ext/v1/transactions?limit&offset&category&direction&q&sort&order` | операции |
| `GET /api/ext/v1/expected-events` · `POST` | ожидаемые платежи и поступления |
| `GET /api/ext/v1/plan-fact?days=` | план-факт |

Ошибки: `401 invalid_token` (нет заголовка, неверный или отозванный токен).

Не сделано: ограничение частоты запросов по токену, права по областям (scopes), срок действия токена.

# Способы входа в аккаунт

У аккаунта может быть email с паролем и до 5 электронных подписей (сертификатов). Любой из них можно добавить или удалить в «Настройки → Способы входа», но **последний оставшийся способ удалить нельзя** (`409 last_method`).

- `GET /api/v1/account/methods`, `POST|DELETE /api/v1/account/email`, `POST /api/v1/account/signatures` (тело как при входе по ЭЦП: подписанный challenge), `DELETE /api/v1/account/signatures/{id}`.
- Привязка подписи проверяется так же, как вход (одноразовый challenge, срок сертификата, cryptcp); подпись, уже привязанная к другому аккаунту, не принимается (`409 signature_taken`).
- Аккаунт, созданный через ЭЦП, не имеет email; служебный адрес `@ecp.invalid` наружу не показывается.

## Данные компании из ЭЦП
При регистрации по подписи компания создаётся по сертификату: название — организация (`O`) или, если её нет, ФИО/CN; ИНН — из OID `1.2.643.100.4` (ЮЛ) или `1.2.643.3.131.1.1`; ОГРН — из `1.2.643.100.1` или `1.2.643.100.5`. При привязке подписи к существующему аккаунту пустые ИНН/ОГРН дополняются, введённые ранее и название не меняются.
