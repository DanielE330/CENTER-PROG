## 2. Что уже есть

- Сервис `gov` (порт 8003): парсинг налогового календаря на nalog.gov.ru (скользящее окно в несколько месяцев), ключевая ставка ЦБ, производственный календарь, предельная база взносов.
- `api`: создание ожидаемых платежей по календарю — ЕНП, аванс УСН по кварталам, НДС тремя платежами; оценка суммы по выписке (`estimate_tax`).
- `integrator` и имитаторы 1С, ЭДО и банка — образец, как строить отдельные сервисы-имитаторы.
- Ожидаемые события с источником `tax` и видимым источником в интерфейсе.

Чего нет: календарь на весь год (сайт отдаёт только окно), единый налоговый счёт (ЕНС), проверка контрагентов по реестрам ФНС, налоговая задолженность и недоимка, учёт риска контрагента в прогнозе, имитатор ФНС.

## 3. Целевая картина

Один новый микросервис `fns` с одной задачей: сведения ФНС о налогоплательщике и его контрагентах. Рядом отдельный имитатор `fns_sim`, как у 1С, ЭДО и банка. Все данные публичные; персональные данные физлиц не хранятся.

```
frontend ── api ──┬── fns ──┬── реальные источники ФНС (включаются флагом FNS_MODE=live)
                  │         └── fns_sim (по умолчанию, FNS_MODE=sim)
                  ├── ledger (ожидаемые события, флаги контрагентов)
                  └── forecast (учёт риска контрагента и неплатежей)
```

Режим `FNS_MODE`: `sim` (по умолчанию, работает везде без сети), `live` (реальные запросы с кэшем и ограничением частоты). Интерфейс не знает, откуда данные: источник показывается подписью.

## 4. Блоки работ

### 4.1 Календарь налоговых платежей на весь год (правила)
Цель: не зависеть от окна на сайте ФНС. Вычислять сроки правилами и сверять с окном nalog.gov.ru.

- ЕНП: 28-е число месяца, перенос на ближайший рабочий день (производственный календарь из `gov`).
- УСН: авансы за I квартал, полугодие и 9 месяцев до 28-го апреля, июля и октября; годовой налог до 28 марта у организаций и до 28 апреля у ИП.
- НДС: тремя равными платежами до 28-го числа каждого из трёх месяцев после квартала.
- Взносы: за работников в составе ЕНП; для ИП фиксированные взносы до конца года и 1% с дохода свыше 300 тыс. до 1 июля следующего года.
- Правила и ставки хранить в данных по годам; проверять на актуальный год до включения.
- Итог: `GET /internal/v1/fns/obligations?inn=&regime=&year=`, расхождение с сайтом ФНС попадает в предупреждение о качестве.

### 4.2 Единый налоговый счёт (ЕНС)
Реальный доступ к ЕНС идёт через личный кабинет налогоплательщика и требует электронной подписи и, для представителей, МЧД. Публичного API без авторизации нет (источник проверить перед работой).

- Имитатор: сальдо ЕНС, начисления, ближайшие срок и сумма по уведомлениям, признак задолженности. Данные детерминированы по ИНН компании из датасета, как у имитатора 1С.
- Контракт сервиса: `GET /internal/v1/fns/ens?inn=` → сальдо, задолженность, ближайшие платежи.
- Прогноз: сальдо ЕНС добавляет к остатку «обязательный платёж»; недоимка попадает как просроченное обязательство с высокой уверенностью.
- Задел на реальную интеграцию: у нас уже есть вход и подпись по ЭЦП (КриптоПро), её можно использовать для авторизации запроса. Это отдельная задача после основных блоков и требует решения владельца.

### 4.3 Проверка контрагента по открытым реестрам
Нужно по ИНН контрагента из выписки: статус (действует, ликвидируется, ликвидирован), дата регистрации, массовый адрес, недостоверные сведения, налоговая задолженность и недоимка, дисквалификация руководителя, признаки банкротства.

- Источники для режима `live`: ЕГРЮЛ/ЕГРИП (egrul.nalog.ru), сервис «Прозрачный бизнес» (pb.nalog.ru), открытые данные ФНС (data.nalog.ru: недоимка, налоговая нагрузка, численность, спецрежимы), реестр банкротств ЕФРСБ (не ФНС, но того же класса).
- **Проверить до реализации:** условия использования и допустимость автоматических запросов, капчи, лимиты, лицензия открытых данных. Если автоматический доступ запрещён или нестабилен, режим `live` не включается, остаётся `sim` и подготовленный адаптер.
- Контракт: `GET /internal/v1/fns/counterparty?inn=` → `{status, registered_at, mass_address, unreliable, tax_debt:{has, amount}, disqualified, bankruptcy:{flag, source}, risk_level, checked_at, source}`.
- Кэш с сроком жизни (сутки), пакетная проверка топ-контрагентов компании, повторные запросы с задержкой, понятные ошибки и поле `source` (`fns_sim` или `egrul`).
- Имитатор: честное распределение статусов по ИНН из датасета (в основном «действует», небольшая доля с задолженностью, редкие ликвидируемые и «банкроты»), ИНН-ы в стиле датасета.

### 4.4 Учёт риска контрагента в прогнозе
- Контрагенты с высоким риском: больше задержка платежа (используются уже реализованные задержки по Каплану–Мейеру) и меньше уверенность в ожидаемом поступлении; контрагент в статусе ликвидации или банкротства исключается из плана с пометкой.
- Новое предупреждение «крупный клиент в зоне риска» с долей ожидаемых поступлений.
- Сценарий «что если крупный клиент не заплатит» использует эту оценку по умолчанию.

### 4.5 Интерфейс
- Страница «Платежи»: источник «ФНС» у налоговых событий (календарь, ЕНС), кнопка «Обновить налоги из ФНС».
- Карточка контрагента (ИНН): статус, задолженность, риск, дата проверки и источник.
- Предупреждения: недоимка на ЕНС, контрагент в зоне риска.
- RU и EN строки, пояснение на языке предпринимателя («у этого клиента долг перед налоговой, оплата может задержаться»).

### 4.6 Инфраструктура и качество
- Сервисы `fns` и `fns_sim` в compose (внутренняя сеть, у `fns` выход наружу только в режиме `live`), порты после 8014 (занять свободные), здоровье `/live`.
- Тесты: контракты на фикстурах (без сети), разбор ответов, правила календаря по годам, устойчивость при недоступном источнике (отдаётся просроченный кэш с пометкой).
- Сквозные тесты и `smoke.sh`: шаг «налоги и контрагенты».
- Документация: `docs/fns.md` (контракты, режимы, ограничения, юридические оговорки).

## 6. Риски

- Реальные API ФНС требуют авторизации, часть — платные или через операторов; публичные веб-интерфейсы могут запрещать автоматические запросы и иметь капчи. Поэтому имитатор и честная пометка источника обязательны.
- Налоговые правила меняются: правила хранить данными по годам и сверять с календарём на nalog.gov.ru.
- Сумма авансов и налогов по выписке — оценка, не расчёт декларации; в интерфейсе подписывать «оценка по выписке».
- Персональные данные: проверять только юридических лиц и ИП, физлиц в реестрах не запрашивать; в журналах не хранить ИНН и содержимое ответов.
