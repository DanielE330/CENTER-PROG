# integrator (Python, порт 8008)

Одна задача: забрать счета и документы из 1С (OData) и ЭДО и привести к единому списку ожидаемых платежей. Банк используется только для остатка (сверка). Состояния нет.

Запуск (из `backend/services`): `uv run uvicorn integrator.app:app --port 8008`. Тесты: `uv run pytest tests/test_integrator.py`.

Env: `ONEC_URL` (http://localhost:8004), `ONEC_USER`/`ONEC_PASSWORD` (demo/demo), `EDO_URL` (:8005), `EDO_TOKEN` (edo-demo-token), `BANK_URL` (:8006), `BANK_CLIENT_ID`/`BANK_CLIENT_SECRET` (demo-client/demo-secret), `INTEGRATOR_TIMEOUT` (5 c), `INTEGRATOR_RETRY_PAUSE` (0.3 c), `INTEGRATOR_TODAY` (as_of по умолчанию; иначе `MOCK_TODAY`, иначе сегодня).
Подключения 1С, введённые компаниями (см. «Как пользователю подключить 1С»): `LEDGER_URL` (http://127.0.0.1:3002; оттуда берутся реквизиты), `INTEGRATIONS_TIMEOUT` (20 c на запрос к настоящей 1С), `INTEGRATIONS_MAX_BYTES` (20 МБ на ответ), `INTEGRATIONS_MAX_SECONDS` (60 c на получение ответа), `INTEGRATIONS_CHECK_LIMIT` (проверок подключения в минуту на компанию, 10), `INTEGRATIONS_ALLOW_HTTP` (1 — разрешить http и любые порты, только для разработки), `INTEGRATIONS_ALLOW_LOOPBACK` (1 вместе с предыдущим — разрешить адреса loopback, для проверки на локальном имитаторе). У ledger для шифрования паролей — `INTEGRATIONS_KEY`.

## GET /internal/v1/obligations?company=C001[&as_of=YYYY-MM-DD][&tenant=<id компании платформы>]
`{company, as_of, onec: "sim"|"live"|null, sources:{onec|edo:{status:ok|error, error, ms, count, duplicates, rejected, skipped}}, items:[...]}`.
Элемент: `external_id, source(onec|edo), kind(invoice|contract|act|upd), direction(in|out), date (срок оплаты), amount_kop (строка), title, counterparty, inn, number, confidence 0..1, status, overdue, duplicate_of (в items всегда null: дубли не включаются)`.

Логика: 1С: `Posted eq true and DeletionMark eq false` (стандартные имена полей OData; имитатор их тоже понимает), пагинация `$top/$skip`, ИНН из `Catalog_Контрагенты`; «Покупателю» = in, «Поставщика» = out. Срок оплаты: дата оплаты в документе (имитатор), иначе дата счёта + отсрочка из `Catalog_ДоговорыКонтрагентов` (`УстановленСрокОплаты`, `СрокОплаты`, календарные или рабочие дни). Оплаченное по счёту вычитается по `РасшифровкаПлатежа.СчетНаОплату_Key` проведённых поступлений и списаний: оплаченные счета не возвращаются, частично оплаченные — остатком. Проведённые `ПлатежноеПоручение` без списания по выписке (`ДокументОснование`) возвращаются как `kind=payment_order` (confidence 0.97, дата не раньше as_of); их сумма снимается со счёта поставщика из `ДокументОснование`, чтобы платёж не считался дважды. ЭДО: курсорная пагинация, «Отклонён» отбрасывается; incoming = out, outgoing = in. Дубль по (номер, ИНН, сумма): остаётся запись 1С, дубль из ЭДО учитывается в `sources.edo.duplicates`, у оставшейся confidence +0.03. Просроченные (срок раньше as_of) возвращаются с `overdue=true` и confidence −0.25. Confidence: 1С проведён 0.9, ЭДО подписан 0.95, отправлен 0.7. Непроведённые и удалённые документы 1С отбрасываются (`skipped`). Ретраи 2 раза при 5xx и сетевых ошибках; упавший источник даёт `status=error`, ответ 200 с данными второго. Договоры (`contract`) пока приходят только если ЭДО отдаст тип «Договор».

`tenant` (его передаёт api при синхронизации): если компания подключила свою 1С, integrator запрашивает реквизиты у ledger (`GET /internal/v1/companies/{tenant}/integrations/onec/credentials` с `x-actor: svc:integrator`) и читает её базу: `onec: "live"`, `as_of` по умолчанию — реальная сегодняшняя дата, а не «сегодня» демо. ЭДО-имитатор в такую выгрузку не подмешивается (`sources.edo.status = "off"`), чтобы демонстрационные документы не попали в данные настоящей базы. У `sources.onec` при ошибке есть `code` (`bad_credentials`, `odata_not_published`, `unreachable`, `timeout`, `url_forbidden`, `ledger_unavailable`…) и понятный `error`. Нет подключения (ledger ответил 404) — прежнее поведение: 1С и ЭДО по env, `onec` = `sim`, если `ONEC_URL` указывает на имитатор (localhost или хост `onec`), иначе `live`. Ledger недоступен — источник 1С получает `status=error`, на имитатор данные не подменяются (`onec: null`).

## POST /internal/v1/onec/check-url `{url}`
Адрес из формы подключения: форма, https, порт, DNS. `200 {ok:true, url}` (канонический адрес) или `422 {error:{code, message}}` (`url_forbidden`, `url_scheme`, `url_userinfo`, `invalid_url`).

## POST /internal/v1/onec/test `{tenant, url?, username?, password?}`
Проверка подключения 1С без повторов. Поля, которых нет в запросе, берутся из сохранённого подключения компании; сохранённый пароль подставляется, только если адрес остался тем же (иначе `422 onec_password_required`; нет ни полей, ни подключения — `422 not_configured`). Лимит `INTEGRATIONS_CHECK_LIMIT` в минуту на компанию (`429 rate_limited`). Ответ 200: `{ok, code, message, source:"live"}`; при успехе ещё `documents` (проведённых счетов, до 100 каждого вида), `more`, `optional_missing` (необязательные объекты, которых нет в публикации), `ms`; при `no_catalog_access` — `missing`. Коды отказа: `bad_credentials` (401), `no_access` (403), `odata_not_published` (404 или страница вместо OData), `no_catalog_access` (нужных объектов нет в составе OData), `unreachable`, `timeout`, `tls_error`, `redirect`, `too_large`, `bad_response`, `url_forbidden`, `url_scheme`, `url_userinfo`, `invalid_url`. Пароль в ответ и в журналы не попадает; ответ на некорректный запрос не повторяет присланные значения.

## Настоящая 1С (1С:Фреш)
Проверено на демо-базе 1С:Фреш («Бухгалтерия предприятия», организация ООО «БЕЛОСНЕЖКА», ИНН 6151021050).
1. В приложении: «Администрирование → Синхронизация данных → Настройки стандартного интерфейса OData». На вкладке «Авторизация» создайте служебного пользователя, на вкладке «Состав» отметьте `Контрагенты`, `ДоговорыКонтрагентов`, `СчетНаОплатуПокупателю`, `СчетНаОплатуПоставщика`, `ПоступлениеНаРасчетныйСчет`, `СписаниеСРасчетногоСчета`, `ПлатежноеПоручение`.
2. Глобальный способ для всех компаний сразу (подключение конкретной компании — «Как пользователю подключить 1С» ниже, оно приоритетнее). В `infra/.env` задайте:
   - `ONEC_URL` — адрес приложения без кода языка, например `https://msk1.1cfresh.com/a/ea/4269703`;
   - `ONEC_USER` и `ONEC_PASSWORD`;
   - `INTEGRATOR_TODAY` — текущая дата.

   Затем перезапустите `integrator`. У него есть выход наружу через сеть `edge`.
3. Наполнить пустую базу демо-документами можно скриптом `python -m integrator.seed_1c_fresh` (запуск из `backend/services` с теми же `ONEC_*`). Скрипт идемпотентный. Что он создаёт:
   - контрагенты с реальными ИНН, у части из них есть задолженность перед бюджетом по открытым данным ФНС на 01.09.2026;
   - договоры с отсрочкой;
   - 9 счетов покупателям: часть оплачена полностью, одна оплата частичная, есть просроченные;
   - черновик счёта;
   - 3 счёта поставщиков;
   - 2 неисполненные платёжки.

Отличия настоящей базы от имитатора, найденные на ней:
- **Имена полей.** Служебные поля по-английски: `Number`, `Date`, `Posted`, `DeletionMark`. Номер документа дополнен пробелами справа.
- **Срок оплаты.** У счёта на оплату нет поля срока оплаты, срок задаёт договор.
- **Пробелы в запросе — только `%20`.** Если пробел закодирован как `+` (так делает httpx в `params`), 1С **молча игнорирует `$filter`** и отдаёт все документы, включая непроведённые. Поэтому клиент собирает запрос сам (`onec.query`).
- **Сравнения в фильтре.** Сравнение по сумме (`СуммаДокумента gt …`) в `$filter` запрещено (ошибка 500 «Операция не разрешена в предложении ГДЕ»): фильтруем только по признакам.

В сервисе (`POST /api/v1/companies/{id}/integrations/sync`) документы 1С становятся ожидаемыми событиями с источником `onec` (на сайте — «1С»), из ЭДО — `invoice`/`contract`.

Тесты на записанных ответах Фреша: `tests/test_onec_fresh.py`, фикстуры лежат в `tests/fixtures/onec_fresh/`. Подключение компании, проверка, защита от SSRF: `tests/test_integrations_onec.py`.

## Как пользователю подключить 1С
Настройки → Интеграции → «1С». Менять подключение может только владелец компании (право `manage`); остальные роли видят статус, даты проверки и синхронизации и откуда идут данные («Имитатор» или «Настоящая 1С»), но не адрес и логин.
1. **Включите OData в 1С.** В 1С:Фреш или 1С:Бухгалтерии откройте «Администрирование → Синхронизация данных → Настройки стандартного интерфейса OData».
2. **Служебный пользователь.** На вкладке «Авторизация» создайте отдельного пользователя только для сервиса (не личную учётную запись) и дайте ему право чтения.
3. **Какие объекты отметить.** На вкладке «Состав»: `Контрагенты`, `ДоговорыКонтрагентов`, `СчетНаОплатуПокупателю`, `СчетНаОплатуПоставщика`, `ПоступлениеНаРасчетныйСчет`, `СписаниеСРасчетногоСчета`, `ПлатежноеПоручение`. Без первых трёх (контрагенты и два вида счетов) проверка не пройдёт; остальные нужны для остатков по счетам, сроков оплаты из договоров и неисполненных платёжек: без них синхронизация работает, но данные беднее (проверка покажет, чего не хватает).
4. **Адрес базы.** Откройте свою базу в браузере и возьмите адрес из адресной строки до номера области, без кода языка в конце и без `/odata`: например `https://msk1.1cfresh.com/a/ea/4269703`.
5. **Введите адрес, логин и пароль**, нажмите «Проверить подключение», затем «Сохранить» (при сохранении проверка выполняется сама). «Синхронизировать сейчас» загрузит счета в ожидаемые события; «Отключить» удалит адрес и пароль (уже загруженные события остаются).

Что проверяет и что отвечает проверка: [POST /internal/v1/onec/test](#post-internalv1onec-test-tenant-url-username-password). Сообщение об ошибке показывает причину и подсказку («1С не приняла логин или пароль», «по этому адресу нет OData», «не хватает объектов в составе OData: …», «сертификат не прошёл проверку»…).

### Как задать ключ шифрования (администратору сервера)
Пароль 1С хранится в `ledger.db` зашифрованным (encrypt-then-MAC на HMAC-SHA256, ключи шифра и имитовставки выводятся из `INTEGRATIONS_KEY`; имитовставка привязана к компании, поэтому значение нельзя перенести в чужую запись). Ключ — любая строка от 16 символов:
- Docker: `./install.sh` и `./run.sh` при первом запуске сами записывают `INTEGRATIONS_KEY` в `infra/.env` (существующий не меняют); вручную: `openssl rand -hex 24`.
- Без Docker: `infra/scripts/dev.sh` создаёт ключ в `data/run/integrations.key` (права 600) или берёт `INTEGRATIONS_KEY` из окружения.
- Без ключа ledger не принимает пароли: `503 integrations_key_missing`, в интерфейсе — предупреждение. Ключ нужно сохранить: с другим ключом сохранённый пароль не расшифровывается (`409 integrations_key_invalid` у integrator, статус «ошибка»), его вводят заново. Резервируйте `infra/.env` вместе с `ledger.db`.

### Безопасность подключения
- **Права.** `PUT|POST|DELETE` — только `manage` (директор), `GET` статусов — любая роль; адрес, логин и флаг «пароль задан» в ответе только у `manage`. Пароля нет ни в одном ответе api, ledger или integrator: единственное место, где он расшифровывается, — внутренний `credentials` у ledger, он отвечает только на `x-actor: svc:integrator` (api этот заголовок сам выставляет пользователем и срезает у входящих запросов), без кэширования.
- **SSRF.** Адрес вводит пользователь, а integrator ходит по нему из внутренней сети, поэтому (`integrator/guard.py`): только `https` (http — лишь при `INTEGRATIONS_ALLOW_HTTP=1`), порты 443 и 8443, без логина и пароля в адресе, имя с точкой (не `localhost`, `.local`, `.internal`, не числовые формы IP). Все IP, в которые имя разрешается в DNS, должны быть публичными: запрещены loopback, link-local (169.254.0.0/16, в том числе метаданные облака), 10/8, 172.16/12, 192.168/16, CGNAT, fc00::/7, multicast и зарезервированные; IPv6 с вложенным IPv4 проверяется по вложенному адресу. Проверка повторяется при каждом соединении, а соединение идёт именно к проверенному IP (DNS rebinding не работает). Редиректы не выполняются (ошибка `redirect`): иначе 1С могла бы перенаправить на внутренний адрес, а клиент заново отправил бы логин и пароль. Переменные окружения прокси игнорируются.
- **Размер и время.** Ответ не больше `INTEGRATIONS_MAX_BYTES`, получение не дольше `INTEGRATIONS_MAX_SECONDS`, запрос — `INTEGRATIONS_TIMEOUT`.
- **Лимит проверок.** 10 в минуту на компанию (`429 rate_limited`; сохранение при исчерпанном лимите проходит без проверки).
- **Пароль к другому серверу не уходит.** Сохранённый пароль используется только при том же адресе (схема, хост, порт); при смене сервера пароль нужно ввести заново (`422 onec_password_required`).
- **Аудит.** В журнал компании пишутся `integrations.onec.connect`, `integrations.onec.check`, `integrations.onec.disconnect`, `integrations.onec.test` (пробная проверка введённых реквизитов), `integrations.sync` — без адреса, логина и пароля.
- **Локальная проверка без интернета.** `INTEGRATIONS_ALLOW_HTTP=1 INTEGRATIONS_ALLOW_LOOPBACK=1` у integrator позволяют подключить имитатор `onec` (`http://127.0.0.1:8004`, логин и пароль `demo`/`demo`); частные сети и link-local остаются закрытыми. На сервере эти переменные не задавайте.

### Контракт api
- `GET /api/v1/companies/{cid}/integrations` -> `{can_manage, key_configured (только manage, иначе null), items:[{kind: onec|edo|bank, connected, source: sim|live, status: not_connected|unchecked|ok|error|sim, last_check_at, last_error, last_sync_at, url?, username?, password_set?}]}` (последние три поля — только manage).
- `PUT .../integrations/onec` `{url, username, password?}` -> то же + `check` (результат проверки или null при исчерпанном лимите). Пустой пароль при том же адресе оставляет сохранённый. Ошибки: `422 url_forbidden | url_scheme | url_userinfo | invalid_url | invalid_username | invalid_password | onec_password_required`, `503 integrations_key_missing`.
- `POST .../integrations/onec/test` `{url?, username?, password?}` (тело необязательно) -> то же + `check` и `recorded` (результат записан в статус, если проверялись сохранённые реквизиты). `429 rate_limited`.
- `DELETE .../integrations/onec` -> 204 (повтор безопасен).
- `POST .../integrations/sync` теперь передаёт `tenant` и возвращает `onec: sim|live`; для подключённой 1С результат попадает в `last_sync_at` или `last_error`.
- ledger хранит в таблице `integration_connections(company_id, kind, url, username, password_enc, status, last_check_at, last_error, last_sync_at, …)`: `GET|PUT|DELETE companies/{cid}/integrations[/onec]`, `PUT .../onec/status {event: check|sync, ok, error?}`, `GET .../onec/credentials` (только integrator).
