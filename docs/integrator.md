# integrator (Python, порт 8008)

Одна задача: забрать счета и документы из 1С (OData) и ЭДО и привести к единому списку ожидаемых платежей. Банк используется только для остатка (сверка). Состояния нет.

Запуск (из `backend/services`): `uv run uvicorn integrator.app:app --port 8008`. Тесты: `uv run pytest tests/test_integrator.py`.

Env: `ONEC_URL` (http://localhost:8004), `ONEC_USER`/`ONEC_PASSWORD` (demo/demo), `EDO_URL` (:8005), `EDO_TOKEN` (edo-demo-token), `BANK_URL` (:8006), `BANK_CLIENT_ID`/`BANK_CLIENT_SECRET` (demo-client/demo-secret), `INTEGRATOR_TIMEOUT` (5 c), `INTEGRATOR_RETRY_PAUSE` (0.3 c), `INTEGRATOR_TODAY` (as_of по умолчанию; иначе `MOCK_TODAY`, иначе сегодня).

## GET /internal/v1/obligations?company=C001[&as_of=YYYY-MM-DD]
`{company, as_of, sources:{onec|edo:{status:ok|error, error, ms, count, duplicates, rejected, skipped}}, items:[...]}`.
Элемент: `external_id, source(onec|edo), kind(invoice|contract|act|upd), direction(in|out), date (срок оплаты), amount_kop (строка), title, counterparty, inn, number, confidence 0..1, status, overdue, duplicate_of (в items всегда null: дубли не включаются)`.

Логика: 1С: `Posted eq true and DeletionMark eq false` (стандартные имена полей OData; имитатор их тоже понимает), пагинация `$top/$skip`, ИНН из `Catalog_Контрагенты`; «Покупателю» = in, «Поставщика» = out. Срок оплаты: дата оплаты в документе (имитатор), иначе дата счёта + отсрочка из `Catalog_ДоговорыКонтрагентов` (`УстановленСрокОплаты`, `СрокОплаты`, календарные или рабочие дни). Оплаченное по счёту вычитается по `РасшифровкаПлатежа.СчетНаОплату_Key` проведённых поступлений и списаний: оплаченные счета не возвращаются, частично оплаченные — остатком. Проведённые `ПлатежноеПоручение` без списания по выписке (`ДокументОснование`) возвращаются как `kind=payment_order` (confidence 0.97, дата не раньше as_of); их сумма снимается со счёта поставщика из `ДокументОснование`, чтобы платёж не считался дважды. ЭДО: курсорная пагинация, «Отклонён» отбрасывается; incoming = out, outgoing = in. Дубль по (номер, ИНН, сумма): остаётся запись 1С, дубль из ЭДО учитывается в `sources.edo.duplicates`, у оставшейся confidence +0.03. Просроченные (срок раньше as_of) возвращаются с `overdue=true` и confidence −0.25. Confidence: 1С проведён 0.9, ЭДО подписан 0.95, отправлен 0.7. Непроведённые и удалённые документы 1С отбрасываются (`skipped`). Ретраи 2 раза при 5xx и сетевых ошибках; упавший источник даёт `status=error`, ответ 200 с данными второго. Договоры (`contract`) пока приходят только если ЭДО отдаст тип «Договор».

## Настоящая 1С (1С:Фреш)
Проверено на демо-базе 1С:Фреш («Бухгалтерия предприятия», организация ООО «БЕЛОСНЕЖКА», ИНН 6151021050).
1. В приложении: «Администрирование → Синхронизация данных → Настройки стандартного интерфейса OData». На вкладке «Авторизация» создайте служебного пользователя, на вкладке «Состав» отметьте `Контрагенты`, `ДоговорыКонтрагентов`, `СчетНаОплатуПокупателю`, `СчетНаОплатуПоставщика`, `ПоступлениеНаРасчетныйСчет`, `СписаниеСРасчетногоСчета`, `ПлатежноеПоручение`.
2. В `infra/.env` задайте:
   - `ONEC_URL` — адрес приложения без кода языка, например `https://msk1.1cfresh.com/a/ea/4269703`;
   - `ONEC_USER` и `ONEC_PASSWORD`;
   - `INTEGRATOR_TODAY` — текущая дата.

   Затем перезапустите `integrator`. У него есть выход наружу через сеть `edge`.
3. Наполнить пустую базу демо-документами можно скриптом `python -m integrator.seed_1c_fresh` (запуск из `backend/services` с теми же `ONEC_*`). Скрипт идемпотентный. Что он создаёт:
   - контрагенты с реальными ИНН, у части из них есть задолженность перед бюджетом по открытым данным ФНС на 01.09.2026;
   - договоры с отсрочкой;
   - 9 счетов покупателям: часть оплачена полностью, одна оплата частичная, есть просроченные;
   - черновик счёта;
   - 3 счёта поставщиков;
   - 2 неисполненные платёжки.

Отличия настоящей базы от имитатора, найденные на ней:
- **Имена полей.** Служебные поля по-английски: `Number`, `Date`, `Posted`, `DeletionMark`. Номер документа дополнен пробелами справа.
- **Срок оплаты.** У счёта на оплату нет поля срока оплаты, срок задаёт договор.
- **Пробелы в запросе — только `%20`.** Если пробел закодирован как `+` (так делает httpx в `params`), 1С **молча игнорирует `$filter`** и отдаёт все документы, включая непроведённые. Поэтому клиент собирает запрос сам (`onec.query`).
- **Сравнения в фильтре.** Сравнение по сумме (`СуммаДокумента gt …`) в `$filter` запрещено (ошибка 500 «Операция не разрешена в предложении ГДЕ»): фильтруем только по признакам.

В сервисе (`POST /api/v1/companies/{id}/integrations/sync`) документы 1С становятся ожидаемыми событиями с источником `onec` (на сайте — «1С»), из ЭДО — `invoice`/`contract`.

Тесты на записанных ответах Фреша: `tests/test_onec_fresh.py`, фикстуры лежат в `tests/fixtures/onec_fresh/`.
