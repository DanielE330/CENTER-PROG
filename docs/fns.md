# Сведения ФНС

Три задачи: налоговые события на весь год (звёздочка 1 кейса), единый налоговый счёт (ЕНС) и проверка контрагентов по открытым реестрам (звёздочка 4). План и обоснование: [fns-integration-plan.md](fns-integration-plan.md), исследование источников: [ФНС_интеграции_план.md](ФНС_интеграции_план.md).

## Как это устроено

```
интерфейс (страница «Платежи», «Настройки → Сведения ФНС») ── api ──┬── fns :8015 ── ЕГРЮЛ/ЕГРИП, открытые данные ФНС, ЕФРСБ
                                                                     ├── ledger  (ожидаемые события, флаги риска, настройки компании)
                                                                     └── forecast (риск клиента: задержка оплаты, исключение из плана)
```

- **Только реальные данные.** Имитатора ФНС больше нет (сервис `fns-sim` и режимы `sim`/`auto` удалены). Контрагенты проверяются по открытым реестрам, в интерфейсе у таблицы стоит пометка «Выгружено из ФНС», перечислены источники и дата набора о задолженности (сейчас 01.09.2026). У сервиса `fns` есть выход наружу (сеть `edge`).
- **Источники.** ЕГРЮЛ/ЕГРИП (egrul.nalog.ru): статус, ликвидация, дата регистрации. Открытые данные ФНС (file.nalog.ru, набор `debtam`, около 70 МБ, 874 002 записи): задолженность перед бюджетом; индекс строится при старте (`FNS_DEBT_PRELOAD=1`). ЕФРСБ: только по логину оператора (`FEDRESURS_LOGIN`/`FEDRESURS_PASSWORD`), без него источник честно «недоступен». «Прозрачный бизнес» закрыт капчей и не используется. Сервис ведёт себя вежливо: честный `User-Agent` с контактом `FNS_CONTACT`, `robots.txt`, не чаще `FNS_MIN_INTERVAL` секунд на сайт, капчи не обходит. Условия использования источников прочитайте сами.
- **ИНН датасета организаторов выдуманные**: в ЕГРЮЛ их нет, статус «Не найден в реестре». По умолчанию это риском не считается (так бывает и при опечатке в выписке); пользователь может включить.
- **Личный кабинет не автоматизируем.** ЕНС в кабинете доступен только по ЭЦП (для представителей ещё и по МЧД). ЕНС берётся только из справки, которую владелец загрузил сам.

## Настройки компании («Настройки → Сведения ФНС»)

Меняют владелец и администраторы (`PUT /api/v1/companies/{cid}/fns/settings`), смотреть могут все. Хранятся в ledger (`company_settings`, раздел `fns`); изменение пересчитывает флаги контрагентов сразу и двигает ревизию данных, поэтому прогноз пересчитывается.

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `sources.egrul`, `sources.data_nalog`, `sources.fedresurs` | вкл. | какие реестры запрашивать; выключенный не запрашивается вовсе (`sources: off`) |
| `risk.bankruptcy`, `liquidation`, `tax_debt`, `unreliable`, `disqualified`, `mass_address` | вкл. | какие признаки считать риском |
| `risk.not_in_registry` | выкл. | считать ли риском ИНН, которого нет в ЕГРЮЛ/ЕГРИП |
| `risk.large_debt_kop` | 50 000 000 (500 тыс. ₽) | долг от этой суммы — «крупный», вес 2 вместо 1 |
| `show_statement`, `show_expected` | вкл. | проверять контрагентов из выписки и/или из 1С и ожидаемых платежей |
| `top` | 20 | сколько крупнейших контрагентов проверять (1–50) |
| `use_in_forecast` | вкл. | учитывать риск в прогнозе; выключено — в ledger пишутся нейтральные флаги |
| `check_after_sync` | вкл. | проверять контрагентов сразу после синхронизации с 1С |

Риск считает `fns` по настройкам, которые api передаёт в теле пакетного запроса: сумма весов (банкротство, ликвидация — 3; нет в реестре, недостоверность, дисквалификация, крупный долг — 2; долг, массовый адрес — 1), высокий от 3, средний от 1. Кэш хранит сырые ответы реестров, поэтому смена настроек не требует повторных запросов.

## Что видит пользователь (страница «Платежи»)

| Блок | Что делает | Роль |
|---|---|---|
| Кнопка «Обновить налоги из ФНС» | Создаёт ожидаемые события на год: ЕНП, авансы и налог УСН, НДС тремя платежами, налог на прибыль, взносы ИП и т.д. Сумма берётся из ЕНС, иначе оценивается по выписке (подпись «оценка по выписке»). Повторный запуск ничего не дублирует. Источник в таблице — «ФНС» | edit |
| Карточка «Единый налоговый счёт» | Сальдо, недоимка, ближайшие платежи, источник и время проверки. Недоимка попадает в прогноз как просроченный платёж | read |
| Кнопка «Загрузить справку ЕНС» | Загрузка справки о состоянии расчётов (XML, КНД 1160080) или простого CSV | edit |
| Таблица «Контрагенты и риски» | Статус, долг перед налоговой, уровень риска, доля в поступлениях, источник и дата проверки | read |
| Предупреждение о рисковом клиенте | Клиент с высоким риском и долей поступлений от 10 %: объяснение простыми словами и ссылка на сценарий «клиент не заплатит». Прогноз добавляет предупреждение `risky_client` | read |

Все маршруты и права: [roles.md](roles.md). Без ИНН в реквизитах компании сведения ФНС недоступны: интерфейс подсказывает, где его указать.

## Как выгрузить справку из личного кабинета

1. Войдите в личный кабинет налогоплательщика (юридического лица или ИП) на nalog.gov.ru своим способом входа.
2. Откройте «Единый налоговый счёт» и закажите «Справку о состоянии расчётов с бюджетом» (КНД 1160080).
3. Когда справка будет готова, скачайте её в формате **XML**.
4. На странице «Платежи» нажмите «Загрузить справку ЕНС» и выберите файл.

Что проверяется: в файле должны быть КНД 1160080 (чужая форма отклоняется), ИНН должен совпадать с ИНН компании, должны находиться сальдо ЕНС или недоимка. XML разбирается терпимо, по именам атрибутов («Сальдо», «Недоим», «Пен»): точная схема меняется от версии формата ФНС. **Это не проверено на настоящем файле из кабинета**, только на образцах по описанию. Если файл не распознан, система скажет об этом и ничего не подставит; тогда используйте CSV.

CSV (UTF-8 или Windows-1251, разделитель `;`, `,` или табуляция, суммы в рублях):

```
as_of;balance;debt;penalty;due_date;due_amount
2026-10-20;-12500,50;12500,50;300;2026-10-28;85000
;;;;2026-11-28;90000
```

`balance` — сальдо ЕНС (минус — долг), `debt` — недоимка, `penalty` — пени, строки с `due_date` и `due_amount` — ближайшие платежи. Файл до 1 МБ. Загруженные файлы не хранятся: в базе остаётся только результат (сальдо, недоимка, пени, ближайшие платежи).

## Контракты сервиса `fns` (внутренние, порт 8015)

| Запрос | Ответ |
|---|---|
| `GET /internal/v1/fns/obligations?inn=&regime=&year=&entity=&employees=` | события года по правилам (сроки со сдвигом на рабочий день, суммы только известные законом), сверка с окном календаря nalog.gov.ru, предупреждения о качестве. Режимы: `usn_income`, `usn_income_expense`, `osno`, `eshn`, `ausn`, `npd`, `patent` |
| `GET /internal/v1/fns/ens?inn=` | сальдо, недоимка, пени, ближайшие платежи из загруженной справки (`source: import`); без справки 404 `fns_ens_not_imported` |
| `POST /internal/v1/fns/ens/import?inn=` `{filename, content_b64}` | разбор справки, сохранение снимка; ошибки `fns_import_*` |
| `GET /internal/v1/fns/counterparty?inn=` | статус, дата регистрации, массовый адрес, недостоверность, долг (`tax_debt.as_of`), дисквалификация, банкротство, `risk_level`, `risk_reasons`, `sources`, `checked_at`, `source`, `exported_from: fns`, `stale` (настройки по умолчанию) |
| `POST /internal/v1/fns/counterparties/batch` `{inns[≤50], settings?}` | пакетная проверка по настройкам компании с общим таймаутом, частичный результат при сбоях |
| `GET /internal/v1/fns/info` | состояние индекса задолженности (дата набора, число записей), задан ли логин ЕФРСБ |

Кэш проверок живёт сутки; если источник недоступен, отдаётся просроченный кэш с пометкой `stale`, а без кэша — честное «не проверен» (`risk_level: unknown`), а не догадка. ИНН не пишутся в журналы (маска в журнале доступа, в логах `httpx` и сервиса), кэш индексируется по хэшу ИНН. Проверяются только юридические лица и ИП.

Правила календаря лежат данными по годам в `backend/services/fns/rules_data.py` с пометкой `checked_against_site` или `verify`: пометка `verify` значит «не сверено с сайтом ФНС, проверьте на актуальный год»; предупреждение об этом возвращается в ответе. Суммы налогов не считаются (кроме фиксированных взносов ИП, они установлены законом), поэтому в интерфейсе сумма без ЕНС подписана как оценка по выписке. Для патента в календарь попадают только взносы: сроки оплаты патента зависят от срока его действия, которого у нас нет.

## Контрагенты из 1С

События из 1С хранят ИНН контрагента (`expected_events.inn`). Поэтому покупатели и поставщики из 1С попадают в таблицу «Контрагенты и риски» вместе с контрагентами из выписки, причём первыми. Доля для них считается от ожидаемых поступлений (пометка «ожид.»). Флаг риска сопоставляется в прогнозе с поступлением по названию из события.

После синхронизации интеграций (`POST …/integrations/sync`) контрагенты с ИНН сразу проверяются: в ответе есть `fns: {checked, flagged, saved}`. Без ИНН компании там будет `error: inn_required`, а сама синхронизация всё равно проходит.

Проверено на демо-базе 1С:Фреш, данные открытого набора ФНС на 01.09.2026:

| Контрагент | Долг перед бюджетом | Риск |
|---|---|---|
| ДОНАГРО | 4 969 978,38 ₽ | средний |
| ЮГСТРОЙ | 4 827 907,23 ₽ | средний |
| ЦТСК | 4 774 883,60 ₽ | средний |
| ЮЖНЫЙ ТОРГОВЫЙ ДОМ | 49 911,18 ₽ | средний |
| ХИМТРЕЙД | 49 835,55 ₽ | средний |
| Тандер, Ростелеком, Яндекс | долга нет | низкий |

Статус и дата регистрации взяты из ЕГРЮЛ. ЕФРСБ без логина оператора недоступен, это видно в `sources`.

Найдено при первом запуске на настоящих сайтах: `PoliteHttp.request` падал (`httpx.Response` не контекстный менеджер), а gzip-ответы распаковывались бы дважды. Исправлено, на это есть тест.

## Прогноз

- Контрагент с высоким риском: оплаты сдвигаются по задержкам Каплана–Мейера с повышенным весом, уверенность в поступлении ниже.
- Контрагент в ликвидации, ликвидирован или в банкротстве: поступления исключаются из плана с пометкой (список `excluded`).
- Предупреждение `risky_client` с долей ожидаемых поступлений; сценарий «клиент не заплатит» по умолчанию берёт такого клиента.

## Запуск и проверка

- Docker: `./run.sh` или `./install.sh` поднимают `fns` вместе со всем остальным; нужен доступ в интернет.
- Без Docker: `infra/scripts/dev.sh` (порт 8015).
- Тесты сервиса: `cd backend/services && uv run --group dev python -m pytest tests/test_fns.py` (реестры подменены транспортом в памяти, сеть не нужна); интеграция в api: `cargo test -p api fns`.
- Сквозная проверка: `infra/scripts/smoke.sh` (шаг «ФНС»).

## Чего нет

- Проверено на ЕГРЮЛ и открытых данных ФНС (25.10.2026), но источники могут изменить формат, ограничить доступ или потребовать капчу. Тесты идут по сохранённым образцам без сети.
- Набор о задолженности ФНС публикует раз в год (сейчас на 01.09.2026): более свежего долга в открытых данных нет.
- Разбор настоящей справки КНД 1160080 не сверен с файлом из кабинета.
- Вход в личный кабинет по ЭЦП и МЧД не делается.
