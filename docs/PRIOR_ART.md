# Готовые решения: что берём, что смотрим, что не трогаем

Поиск по GitHub 2026-10-23, два прохода. Искали по названиям и описаниям, по README (`in:readme`), на русском и английском: cash flow forecast/forecasting, runway, overdraft, balance forecast, AI CFO, кассовый разрыв, платёжный календарь, прогноз денежных потоков, категоризация выписок, 1CClientBankExchange, производственный календарь, решения прошлых кейсов «Центр-инвеста». Звёзды и даты последнего коммита указаны на день поиска.

Короткий вывод. Готового решения нашего кейса нет. Ближе всего — небольшие проекты, которые делают тот же конвейер (категоризация → регулярные платежи → прогноз остатка → предупреждение) для личных финансов или для западного SMB. Код из них берём точечно и только при подходящей лицензии, а идеи и способы оценки — смело. Время по-настоящему экономят большие проекты как строительные блоки: модели прогноза, каркас фронта, русская категоризация.

## Правило по лицензиям

Код в наш репозиторий попадает только под MIT, Apache-2.0, BSD или MPL-2.0. Проекты под AGPL/GPL только читаем: AGPL обязывает раскрывать код SaaS, а это ломает продажную модель. Проекты без лицензии юридически нельзя копировать вообще, они только для идей. В CI это проверяют `cargo-deny`, `pip-licenses` и `license-checker` для pnpm.

## Сознательно не берём

**LiteLLM** ([BerriAI/litellm](https://github.com/BerriAI/litellm), 62k★, MIT кроме `enterprise/`). Это самый очевидный готовый мультипровайдерный LLM-шлюз, и он закрыл бы `llm-gateway` за час. Не берём из-за цепочки поставки. В трекере проекта:

- 2026-03-24: версии 1.82.7 и 1.82.8 на PyPI содержали `litellm_init.pth`, крадущий учётные данные. PyPI поместил пакет в карантин;
- 2026-10-21: версия 1.107.0 и Docker-образы `latest`/`main-stable` собраны из поддельного репозитория `Berri-AI/litellm` и содержат стилер и загрузчик RCE.

Шлюз, через который проходят все ключи провайдеров и данные клиентов, — худшее место для зависимости с такой историей. Наш `llm-gateway` на Rust покрывает 5 провайдеров. Четыре из них говорят на OpenAI-совместимом протоколе (OpenAI, OpenRouter, llama.cpp, Gemini через его OpenAI-совместимый endpoint), отдельный адаптер нужен только для Anthropic Messages API. Это примерно день работы, и этот же случай — живой пример для слайда про supply chain: почему у нас закреплены digest, есть SBOM и подписи.
