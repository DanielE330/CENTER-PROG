# Оценка прогнозной модели (rolling-origin backtest)

Воспроизведение: `cd backend && cargo run --release -p forecast --bin eval -- [--limit N] [--step 14] [--compare] [--csv] [--calibrate] [--debug C001] [--perf]`
(запускать из корня репозитория; CSV по компаниям пишется в `data/eval/`). Датасет: 150 компаний, 142 имеют историю >= 150 дней
для backtest; origin каждые 14 дней, первая точка через 120 дней истории, 200 траекторий, фиксированный seed.

**Нормировка.** Ошибка каждой компании = MAE остатка / медианный недельный оборот компании (медиана по неделям суммы |операций|), в %.
Показаны среднее и медиана по компаниям (mean/median). `beat/orig` — доля контрольных точек, где модель строго точнее обеих
базовых линий; `beat/comp` — доля компаний, где MAE модели ниже обеих базовых. `cov` — доля фактических остатков внутри [p10, p90] (идеал 0.80).
Базовые линии: last-value (остаток не меняется) и drift (средний прирост за последние 28 дней).

## Калибровка вероятности разрыва (P(остаток < 0 за 30 дн.))

Сырая вероятность (доля траекторий с разрывом) сильно завышена в диапазоне 0.2-0.95: счёт у многих компаний «прижат» к нулю, владелец
пополняет/выводит остатки, чего поток-модель не знает. Траектории и NMAE не менялись; поверх сырой доли добавлена **калибровка**
(`calibrate_risk` в `forecast.rs`), в JSON `risk.shortfall_probability` = калиброванное значение, `risk.raw_shortfall_probability` = сырое (новое поле);
`risk.level` считается по калиброванному (пороги 0.05 / 0.2 / 0.5 прежние, но теперь это реальные частоты).

Модель калибровки: логистическая регрессия (L2, Ньютон) на безразмерных признаках, масштаб - медианный недельный оборот компании:
logit(сырая P), asinh(открытие/масштаб), доля дней в минусе за 120 дн., asinh(минимум остатка за 120 дн./масштаб), asinh(медиана остатка за 120 дн./масштаб).
Признаки истории не зависят от сценария, поэтому итоговая P монотонна по сырой (сценарий, повышающий сырой риск, не снижает итоговый). Дополнительно
«страховка»: если медианная траектория уходит ниже нуля более чем на 0.5 недельного оборота (крупный известный платёж, сценарий - не колебание около нуля),
итог не ниже сырой P с плавным весом (полностью при дефиците 1.5+ недель). При отрицательном открытии калибровка не применяется (риск = сырая, около 1).
Коэффициенты зашиты константами `CAL_B/CAL_W` (подобраны на всех 5314 контрольных точках; `eval --calibrate` печатает и перепроверяет их).

**Честная оценка** (`eval --calibrate`): калибратор обучается без тестовых данных - а) leave-company-out, 5 фолдов по компаниям; б) по времени: обучение на origin 0-19,
тест на origin >= 23 (зазор 3 origin больше горизонта 30 дней; 2248 точек теста). Выбор набора признаков сделан по этим же схемам, поэтому оценка немного оптимистична (5 вариантов сравнивалось).

| метрика | до (сырая), LCO-выборка | после, leave-company-out | до, временной тест | после, временной тест |
|---|---|---|---|---|
| Brier | 0.0825 | **0.0145** | 0.0860 | **0.0124** |
| ECE (6 бинов) | 0.142 | **0.0015** | 0.144 | **0.0066** |
| порог 0.5: precision / recall | 0.22 / 0.80 | 0.93 / 0.66 | 0.24 / 0.84 | 0.99 / 0.70 |
| порог 0.7: precision / recall | 0.39 / 0.71 | 0.97 / 0.62 | 0.38 / 0.71 | 1.00 / 0.67 |
| порог 0.9: precision / recall | 0.76 / 0.66 | 0.98 / 0.52 | 0.72 / 0.69 | 1.00 / 0.59 |

Для сравнения (LCO, Brier / ECE): изотоническая регрессия по одной сырой P 0.0205 / 0.0134; Platt по сырой P 0.0216 / 0.0145; логистика на сырой P + открытие 0.0198 / 0.0180;
+ доля дней в минусе 0.0153 / 0.0054; выбранная (+ история 120 дн.) 0.0145 / 0.0015; со всеми 8 признаками 0.0143 / 0.0009 (не взята: признаки по траекториям зависят от сценария и ломают монотонность).
Главный вклад даёт не пересчёт самой шкалы (Platt/изотоника дают Brier 0.021), а признаки «прижатости»: доля дней в минусе и минимум остатка за 120 дней.

In-sample (боевая модель на всём датасете, `eval --csv`): Brier 0.0121, ECE 0.002; порог 0.5: precision 0.94 / recall 0.72 (tp 166, fp 10, fn 63); 0.7: 0.97 / 0.71; 0.9: 0.99 / 0.66.
NMAE остатка (h=7/14/30: 38.1 / 51.4 / 65.5 %), покрытие p10-p90 и beat/orig не изменились (калибруется только вероятность разрыва).

Ограничения: 229 положительных окон в 142 компаниях, синтетический датасет (поведение владельца по «прижатости» одинаково устроено у многих компаний - на реальных данных
коэффициенты, прежде всего вес доли дней в минусе, надо переобучить: `eval --calibrate` печатает готовые `CAL_B/CAL_W`); в середине диапазона (0.2-0.95) мало наблюдений (n=13-43 в бинах), поэтому частоты там известны с точностью около ±10-15 п.п.; recall при высоких порогах ниже, чем у сырой P (0.52 против 0.66 при 0.9): часть разрывов, которых не ждёт история
(счёт был «здоров» 120 дней), калиброванная модель оценивает как маловероятные; калибровка обучена на горизонте 30 дн. и применяется ко всем горизонтам; полоса p10-p90 на 7-14 дней по-прежнему узковата (0.72-0.76).

## Что изменено и почему

1. Календарь РФ (пн-пт, праздники, рабочие субботы 2024-2025, переносы 2024-2027): регулярные платежи, якорь которых на выходной, переносятся на следующий рабочий день;
   сдвиги (джиттер, задержка оплаты) считаются в рабочих днях; остаточный поток и среднее строятся только по рабочим дням, выходные дают нулевой поток.
2. Пропуски выписки: разрыв между датами операций > 5 дней, >= 3 пустых рабочих дня, и остаток «не сходится» (остаток дня != прошлый остаток + операции дня).
   Эти дни исключаются из окна остаточного потока (окно ~86 рабочих дней расширяется назад), месяцы с пропуском не участвуют в обнаружении регулярностей; в `quality.notes` пишется число и длительность пропусков.
   Праздничные каникулы и «тихие» периоды с сошедшимся остатком пропусками не считаются.
3. Регулярности: второй уровень ключа «контрагент + основа назначения платежа» (банк получает зарплату-аванс, зарплату-расчёт, кредит, комиссию под одним ИНН — раньше не обнаруживались).
4. Сжатие дрейфа: линейный дрейф статистической части (регулярные + остаточный) снят, форма внутри горизонта сохранена на 50%; сценарные сдвиги/события этим не затрагиваются.
5. Возврат к среднему: остаток тянется к медиане за 120 дней, 1.5% разрыва в рабочий день. Это единственное, что реально улучшило 30-дневную ошибку сверх last-value.
6. Овердрафт: заметка в `quality.notes`, риск = 1 при отрицательном открытии; <60 дней истории -> `quality.level = low`; горизонт 0 и пустые окна не паникуют.
7. Backtest: `band_coverage` по горизонтам, `alarm_tp/fp/fn`, `backtest_with(params)`; `eval`-бинарник (`backend/forecast/src/bin/eval.rs`). Скорость: 1 прогноз на 222k операций = 0.6 с (release, 1000 траекторий).

Не помогло: затухание только остаточного среднего (при этом регулярные расходы остаются без компенсации доходом — хуже); weekday_mean и ewma
(после сжатия равны block, до него хуже; ewma хуже всех — реагирует на шум); сокращение/увеличение окна 60/130/180 рабочих дней (без эффекта);
число траекторий 200 -> 1000 (без эффекта).

## Особенности данных

- Остатки близки к стационарным: средний дрейф окна экстраполировать вредно, наивный прогноз очень силён.
- Дубли строк (~19 случаев): остаток дня не сходится на малых интервалах; не удаляются (одинаковые платежи бывают законными).
- Около 35 реальных пропусков (остаток «скачет» после разрыва 9-52 дня); рабочие субботы 02.11.2024, 28.12.2024, 01.11.2025; 1266 дней с отрицательным остатком.
- Поведение владельца: счета «прижаты» к нулю (пополнение/вывод), поэтому сырая P(разрыв) в диапазоне 0.2-0.8 завышена (исправлено калибровкой); полоса p10-p90 на 7-14 дней узковата (0.72-0.76 вместо 0.80).

## Задержки оплат по Каплану-Мейеру (`recurring-bootstrap/3`)

Для ожидаемых поступлений-счетов и просроченных регулярных поступлений задержка берётся из кривой Каплана-Мейера контрагента со сжатием к общей кривой (вес n/(n+5)); `eval --no-km` возвращает прежнюю таблицу сдвигов. Сверка на всех 142 компаниях (200 траекторий, шаг 14 дней): NMAE h=7/14/30 (среднее) 38,1 / 51,4 / 65,5 % и покрытие P10-P90 0,715 / 0,760 / 0,815 с KM против 0,716 / 0,761 / 0,814 без него; Brier 0,0121, ECE 0,0022, precision 0,943 / recall 0,725 при P >= 0,5 одинаковы. Калибровка (`CAL_B/CAL_W`) не менялась. Бэктест не содержит ожидаемых событий, поэтому изменение здесь почти не заметно (затронуты только просроченные регулярные поступления); эффект на счетах проверяется юнит-тестами `delays.rs` и на реальных данных с 1С/ЭДО.

## Обновление без полного пересчёта (`--incremental K`)
Режим компании «Обновлять по новым данным» (`docs/ml-architecture.md`, раздел 3). В каждой контрольной точке модель обучена за K дней до неё, затем операции дописываются по одному дню через `Fitted::advance`, и по ним строятся траектории. Если дописать нельзя, точка считается полным пересчётом, как это сделал бы сервис. Остальное как в основном прогоне: 142 компании, шаг 14 дней, 200 траекторий.

| Модель | NMAE mean h=7 / 14 / 30 | Brier | ECE | precision / recall при P ≥ 0,5 |
|---|---|---|---|---|
| полный пересчёт | 38,1 / 51,4 / 65,5 | 0,0121 | 0,0022 | 0,943 / 0,725 |
| дописывание 7 дней | 38,1 / 51,4 / 65,5 | 0,0121 | 0,0023 | 0,943 / 0,725 |
| дописывание 14 дней | 38,1 / 51,4 / 65,6 | 0,0121 | 0,0023 | 0,943 / 0,725 |
| дописывание 30 дней | 38,3 / 51,5 / 65,5 | 0,0121 | 0,0023 | 0,938 / 0,725 (одна ложная тревога сверх полного) |

Медиана NMAE отличается от полного пересчёта не больше чем на 0,7 п. п. в любую сторону. Поэтому полный пересчёт обязателен раз в 30 дней и при росте истории больше чем на 25 %.

**Скорость** (`eval --perf`, история всего датасета в одном прогнозе, 222 420 операций, 1000 траекторий, 30 дней):

| Шаг | Время |
|---|---|
| полный пересчёт (`fit` + `simulate`) | 0,635 с |
| `fit` | 0,603 с |
| `advance` (+356 операций за день) | 0,0016 с |
| `simulate` | 0,017 с |
| **обновление по новым данным** (`advance` + `simulate`) | **0,018 с** (в 35 раз быстрее) |

Если изменились только события, сценарий или горизонт, выполняется только `simulate` по сохранённой модели. Результат совпадает с полным пересчётом (тест `simulate_on_fitted_equals_forecast_and_survives_serde`). Окно остаточного потока после дописывания по дням совпадает с окном полного обучения (тест `advance_by_days_rebuilds_the_same_residual_window_as_a_full_fit`).
