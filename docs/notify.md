# Почта (сервис notify)

Сервис `notify` (`backend/services/notify`, порт `:8014`, только внутренняя сеть) — единственный почтовый шлюз платформы. Он собирает письма из шаблонов (HTML и текст, только на русском), ставит их в очередь и отправляет по SMTP. Ссылки с токенами выпускает `auth`: в базе хранится только sha256 токена, каждая ссылка срабатывает один раз. Связывает их `api` (`backend/api/src/mail.rs`).

**Что и когда рассылать, решает `notifier`.** У него одно расписание и одни пороги для Telegram и для почты; их задаёт владелец или администратор в блоке «Расписание уведомлений (Telegram и почта)». notifier отправляет каждое сообщение и в Telegram, и в `notify`, а тот рассылает его письмом участникам компании, у которых включена почта. Без токена Telegram-бота расписание тоже работает, тогда только почтой.

## Какие письма бывают

| Письмо | Когда | Получатель |
|---|---|---|
| Подтверждение почты | регистрация, смена email, задание email после входа по ЭЦП | сам пользователь; ссылка на 24 часа |
| Восстановление пароля | «Забыли пароль?» на экране входа | владелец адреса; ссылка на 1 час, не больше 3 писем в час |
| Приглашение по ссылке | «Пригласить» с указанным email (`/team/invites`) | приглашённый; код `/?invite=` на 7 дней; не больше 50 писем в час на компанию |
| Приглашение с паролем | владелец или администратор добавил сотрудника с паролем | сотрудник; ссылка «задать пароль» на 72 часа, пароль остаётся запасным |
| Сброс пароля сотрудника | «Сбросить пароль» в списке сотрудников | сотрудник получает ссылку; если письмо не ушло, сайт показывает пароль |
| Алерт о кассовом разрыве и «риск снизился» | расписание notifier (за 7, 3 и 1 день) | подписка **alerts** |
| Пропущенные платежи | проверка план-факта notifier каждые 3 часа (о каждом платеже один раз) | подписка **alerts**; письмо в жёлтой рамке |
| Риск-отчёт, итоги недели, итоги месяца | расписание notifier или «Отправить сейчас» | подписка **reports**; график внутри письма, к итогам месяца приложен Excel |
| Блокировка компании | оператор заблокировал компанию (`backoffice`) | все участники |

## Подписки
Блок «Уведомления на почту» в Настройках есть у каждого участника:
- два переключателя: «Алерты о кассовом разрыве» и «Отчёты»;
- кнопка «Отправить тестовое письмо».

По умолчанию почта включена у владельца и администраторов, у аналитиков и наблюдателей выключена. Пока почта не подтверждена, войти можно, но рассылки не приходят и включить их нельзя (409 `email_not_verified`). В каждой рассылке есть ссылка «Отписаться» (выключает и алерты, и отчёты) и заголовок `List-Unsubscribe`.

## Эндпоинты
Публичные (`api`):

| Метод и путь | Сессия | Что делает |
|---|---|---|
| `POST /api/v1/auth/password/forgot {email}` | нет | всегда 202: по ответу нельзя понять, зарегистрирован ли адрес |
| `POST /api/v1/auth/password/reset {token, password, password_confirm}` | нет | новый пароль по ссылке; все сессии закрываются |
| `POST /api/v1/account/email/verify {token}` | нет | подтверждение почты |
| `POST /api/v1/notifications/unsubscribe {token}` | нет | отписка |
| `POST /api/v1/account/email/resend` | да | письмо подтверждения ещё раз (429, если чаще раза в минуту) |
| `GET` / `PUT /api/v1/account/notifications` | да | свои подписки `{alerts, reports}` и статус почты |
| `POST /api/v1/account/notifications/test` | да | тестовое письмо себе |

Внутренние эндпоинты `notify`:
- `POST /internal/v1/send {kind, to, data, dedup_key?}` — служебные письма (`verify_email`, `reset_password`, `invite`, `team_invite`, `member_reset`, `company_banned`, `test`); для `team_invite` при превышении лимита 429 `mail_limited`;
- `POST /internal/v1/companies/{cid}/broadcast {kind, key, subject, html, path?, chart_png_b64?, xlsx_b64?, xlsx_name?}` — рассылка notifier: `kind` = `gap` | `gap_resolved` | `risk` | `week` | `month`, `html` в формате Telegram-HTML (переводится в безопасный HTML письма), повтор с тем же `key` второго письма не создаёт, вложения до 5 МБ;
- `GET /internal/v1/companies/{cid}/subscribers` → `{alerts, reports}` — число подписчиков;
- `GET /internal/v1/companies-with-subscribers` — компании, которые планировщик notifier обходит даже без Telegram (кэш 5 минут);
- `GET|PUT /internal/v1/prefs/{user_id}`, `POST /internal/v1/unsubscribe`, `DELETE /internal/v1/users/{user_id}`.

Страницы SPA для ссылок из писем открываются без входа: `/verify-email?token=`, `/reset-password?token=` (с `&invite=1` для приглашения), `/unsubscribe?token=`, `/?invite=<код>`.

## Доставка
- **Очередь.** Письмо сначала попадает в outbox (SQLite, том `notify-data`); вложения хранятся до отправки.
- **Повторы.** При сбое SMTP следующая попытка через 1, 5, 30 и 120 минут, затем статус `failed`. В журнал пишутся только id письма и класс ошибки, без адресов и содержимого.
- **Mailpit по умолчанию.** Все письма ловит Mailpit: http://localhost:8025 (доступен только с этой машины).
- **Реальный SMTP.** В `infra/.env` задайте `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURITY=ssl|starttls`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM`. Для совместимости понимаются и `SMTP_FROM`, `SMTP_SSL=1`, `SMTP_STARTTLS=1`. Ссылки в письмах строятся от `PUBLIC_URL`.
- **Сеть.** У `notify` две сети: `internal` для данных и `mail` для выхода к SMTP.
