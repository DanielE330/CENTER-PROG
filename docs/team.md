# Команда компании: роли и приглашения

Несколько веб-пользователей работают в одной компании. Модель: компания в ledger по-прежнему принадлежит одному `owner_id`, а сервис `auth` хранит, кто в какую компанию входит.

## Как устроено
- Пользователь без записи членства — **владелец** собственной компании (tenant = его id).
- Участник записан в `memberships(user_id, tenant_id, role)` и работает в компании владельца: BFF ищет компанию в ledger по `tenant_id`, а не по id участника. ledger менять не пришлось.
- Выход из команды или удаление участника возвращают человека в его собственную компанию (она не удаляется), поэтому данные не теряются.
- `session` и `tokens/verify` отдают `tenant_id` и `role`, роль считается при каждом запросе: смена роли и удаление действуют сразу, в том числе на API-токены участника.

## Роли
| Роль | Может |
|---|---|
| Владелец | всё; управляет всеми; единственный выдаёт роль «Администратор» |
| Администратор | команда (аналитики, наблюдатели), Telegram-настройки, отделы и политики, согласие на ИИ, переименование компании |
| Аналитик | импорт выписок, платежи, сценарии, синхронизация интеграций, цели недели и ретро |
| Наблюдатель | только просмотр (включая личную привязку Telegram) |

Правила проверяются на сервере (`need_for` в `backend/api/src/http.rs`): по методу и пути. GET — наблюдатель; изменение данных — аналитик; переименование компании, Telegram-настройки (кроме целей и ретро), `notifications/team` — администратор. Внешний API по токену: GET — наблюдатель, остальное — аналитик, роль берётся у владельца токена. Админ не может приглашать админов и менять равных себе, владельца изменить нельзя; число участников ограничено 20.

## Передача владения
Владелец передаёт владение участнику (`POST /api/v1/team/transfer {user_id}`), сам становится администратором. id компании в ledger не меняется (tenant остаётся прежним), поэтому данные, токены и чаты на месте: меняются только роли в `memberships`. Telegram-роли обоих обновляются автоматически. Владелец не может выйти из команды, пока не передал владение. Бывшего владельца нельзя удалить или дать ему выйти (удаление записи вернуло бы ему права исходного владельца), его можно только понизить до аналитика или наблюдателя.

## Приглашения
Администратор создаёт одноразовую ссылку `/?invite=<код>` с ролью (7 дней, в базе только sha256 кода). Приглашённый входит или регистрируется и подтверждает вступление (экран «Приглашение в команду»). Нельзя принять приглашение, если человек уже в команде или у него самого есть участники. Отозвать ссылку можно в «Настройки → Команда».

**Привязка к email.** Если при создании указать email, приглашение принимает только пользователь с таким адресом (пользователь, вошедший по ЭЦП без email, не подойдёт: сначала нужно привязать почту). Неудачная попытка другого пользователя код не сжигает. Письмо отправляет `notifier` по SMTP (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, `SMTP_SSL=1` для порта 465, `SMTP_STARTTLS=1` по умолчанию); в письмо идёт только текст со ссылкой, пароль и код в логи не попадают. Заголовки очищаются от переводов строк, адрес проверяется. Без SMTP письмо не уходит, а сайт показывает ссылку, чтобы передать её вручную.

## Журнал действий
Страница «Журнал» (владелец и администраторы, `GET /api/v1/team/activity?limit&offset&q`) показывает, кто и что делал: приглашения и смены ролей, передачу владения, цели (в том числе отметки в Telegram-боте как `tg:<id>`), настройки уведомлений, импорты, платежи, прогнозы, токены. Записи лежат на диске в `audit_events` ledger (том `ledger-data`, индекс по компании), автоматически не удаляются и переживают перезапуск;  имена участников подставляет BFF. В журнал пишутся только состоявшиеся действия, отклонённые по правам нет; тексты вопросов к консультанту и тела запросов не сохраняются.

**Экспорт.** Кнопка «Скачать CSV» (`GET /api/v1/team/activity/export?q=`) выгружает весь журнал с тем же фильтром (до 20 000 строк, UTF-8 с BOM, разделитель `;`, открывается в Excel). Значения, похожие на формулы (`=`, `+`, `-`, `@`), экранируются апострофом, чтобы чужой текст не выполнился в Excel. Сам экспорт попадает в журнал.

**Лимит писем:** не больше 50 приглашений по email в час на компанию; при превышении сайт предложит передать ссылку вручную.

## Связь с Telegram
Любая роль может привязать свой Telegram (`POST /companies/{cid}/notifications/link`): роль в боте выводится из веб-роли. Владелец и администратор — `admin`, аналитик — `rater`, наблюдатель — `viewer`. При смене веб-роли BFF сообщает боту (`notifications/web-role`), при удалении из команды личные чаты человека отключаются. Роли участников групп, у которых нет веб-аккаунта, по-прежнему назначает администратор («Команда и политики»).

## API (BFF)
`GET /api/v1/team/members` · `GET|POST /api/v1/team/invites` · `DELETE /api/v1/team/invites/{id}` · `PATCH|DELETE /api/v1/team/members/{uid}` · `POST /api/v1/team/leave` · `POST /api/v1/team/accept`. `GET /api/v1/auth/me` теперь возвращает `role` и `user_id`.

## Ограничения
- Пользователь состоит только в одной команде.
- Приглашение без email работает для того, кто открыл ссылку первым: передавайте её адресату напрямую или указывайте email.
