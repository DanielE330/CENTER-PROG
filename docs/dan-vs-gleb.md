# Различия веток `dan` и `gleb` (DanielE330/CI-hack)

Состояние на 24.10.2026: `dan` = `94e6495`, `gleb` = `353ade5`. Ветка `dan` включает `main` и `ura`; её подпапку `gleb/` (точную копию ветки `gleb`) в сравнении не учитываем.

Ветки решают одну задачу: прогноз денежного потока и кассовых разрывов. Сделаны они по-разному. В `dan` сильнее продукт: функции для пользователя и точность прогноза. В `gleb` сильнее платформа: безопасность, мультиарендность, ИИ-консультант и инфраструктура.

## Есть в обеих ветках

- Импорт CSV-выписки, автокатегоризация и ручная смена категории.
- Прогноз остатка по дням с коридором P10–P90 и Монте-Карло.
- Разрыв с датой, суммой, вероятностью и причинами.
- Сценарии «что если», план-факт, ручные будущие платежи, налоговый календарь ЕНП.
- Бэктест и сравнение с наивными моделями, учёт пропусков в выписке, овердрафта и короткой истории.
- Консультант с ответами по шаблону или правилам.

## Есть в `dan`, нет в `gleb`

**Прогноз**
- **Калиброванная вероятность разрыва.** Логистическая регрессия по истории: Brier 0,083 → 0,015, при пороге 0,5 точность 0,93. Это самое сильное место `dan`.
- Модель точнее наивной на 3–5% на 30 днях, проверена на 142 компаниях. В `gleb` наивная модель пока точнее, а бэктест шёл на 30 компаниях.
- Поиск недельных и месячных регулярных платежей, российский производственный календарь 2024–2027.
- «Мост до сегодня»: если выписка старая, прогноз строится от её конца до сегодняшнего дня.
- Оценка сумм авансов УСН (6% или 15%) и НДС по выписке. В `gleb` есть только сроки уплаты по режиму.
- Уровень качества данных (good/medium/low) с пояснениями.

**Вход и аккаунт**
- Вход и регистрация по ЭЦП: проверка ГОСТ-подписи на Python без КриптоПро, название компании берётся из сертификата.
- Несколько способов входа на один аккаунт: пароль и до 5 сертификатов.
- **Внешний API по токенам** (`/api/ext/v1/*`) для 1С, BI и скриптов, токены управляются в настройках.

**Интеграции**
- Сервис `gov`: ключевая ставка ЦБ, производственный календарь, налоговый календарь ФНС, страховые взносы.
- Сервис `integrator` и имитаторы 1С (OData), ЭДО и банка. Синхронизация обязательств в будущие платежи идемпотентна, имитаторы умеют искусственно сбоить.

**Интерфейс**
- Дизайн «Fintech Minimal» на Tailwind и ECharts, светлая и тёмная темы, интерфейс на русском и английском.
- Импорт XLSX и предпросмотр импорта с подтверждением, история импортов.
- Серверные фильтры, поиск и сортировка операций, недельные потоки, KPI на главной, карточка ключевой ставки.

**Запуск**
- `run.sh`: всё поднимается одной командой.

## Есть в `gleb`, нет в `dan`

**Мультиарендность и безопасность**
- Keycloak: организации как тенанты, роли owner/accountant/viewer, двухшаговый вход, token exchange. В `dan` свои сессии, и у пользователя одна компания.
- PostgreSQL с RLS у каждого сервиса. В `dan` SQLite без RLS, изоляция компаний держится на проверках в коде.
- mTLS между всеми сервисами: внутренний CA step-ca, SPIFFE-идентификаторы, автопродление сертификатов. Postgres и NATS принимают только сертификаты, паролей нет.
- BFF-шлюз с зашифрованными сессиями и CSRF-токеном.

**События**
- NATS JetStream, outbox, идемпотентные обработчики, очередь ошибок (DLQ).
- Обновления в реальном времени через SSE, без перезагрузки страницы.
- Отдельный сервис `alerts`: предупреждения о разрывах и просрочках со схлопыванием повторов.

**Данные и ML**
- Импорт формата 1С (1CClientBankExchange) и проверка непрерывности остатка.
- Категоризатор с правилами и ML-моделью, покрытие правил 99,7%. Пользовательские категории применяются ко всем операциям контрагента.
- Определение режима налогообложения по выписке с подтверждением пользователем.
- Восстановление выставленных счетов по назначениям платежей и учёт задержек оплаты (Каплан–Мейер), автоматическое закрытие счетов оплатами.
- Демо-режим «Прошла неделя»: следующие операции подаются через обычный импорт, видны пересчёт и план-факт.
- Синтетический генератор выписок и гейт качества прогноза в CI.

**ИИ-консультант**
- Hermes Agent на облачных моделях (Claude, ChatGPT, Gemini, OpenRouter) с 8 MCP-инструментами.
- Консультант только предлагает, а пользователь принимает или отклоняет («Предложения»).
- `llm-gateway`: маскирование контрагентов, ИНН и счетов, бюджет токенов на тенанта, аудит обращений.

**Пороги**
- Неснижаемый остаток и лимит овердрафта, предупреждения двух уровней.

**DevSecOps и эксплуатация**
- CI на GitHub: clippy, ruff, cargo-deny, pip-audit, semgrep, gitleaks, hadolint и trivy. Образы подписываются cosign, все 12 сейчас без HIGH/CRITICAL уязвимостей.
- Процесс веток `feature → домен → tested → stable` с branch-guard.
- Podman Quadlet и Ansible-роли для стенда: hardening, секреты, бэкапы, деплой-агент.
- 15 e2e-тестов против живого стека.
- Документы `ARCHITECTURE`, `PRODUCTION_PLAN` (техника и продажи) и `MVP`.

## Как сливать

Предлагается за основу взять платформу `gleb`: безопасность, мультиарендность и ИИ-консультант сложно вставить потом. В неё переносим из `dan` по приоритету:

1. **Прогнозную модель с калибровкой** — главное для оценки жюри. Есть два пути: переписать её на Python в сервисе `forecast` за тем же интерфейсом или вынести Rust-ядро `fc_model` в отдельный сервис. Бэктест покажет, какая модель лучше на одних и тех же данных.
2. **ЭЦП-вход** — как способ входа через Keycloak (x509 или свой провайдер).
3. **Сервисы `gov` и `integrator` с имитаторами** — в схему коннекторов `gleb` они встраиваются почти без изменений.
4. **Внешний API по токенам** — через Keycloak (service accounts) или отдельный модуль в gateway.
5. **Фронтенд `dan`** (он богаче) — подключить к API `gleb`. Это самая объёмная часть работы.

## Внимание

В `dan` лежит `data/demo/statements/C001.csv`. Он побайтово совпадает с выпиской C001 из датасета организаторов, а репозиторий публичный. Чтобы убрать файл, одного удаления мало: он останется в истории ветки.
