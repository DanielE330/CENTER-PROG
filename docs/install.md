# Установка одной командой и двухфакторная защита оператора

## Установка

Нужен только Docker (Compose v2) и curl.

```
./install.sh                       # локально: http://localhost:3000, оператор — http://localhost:3000/operator
./install.sh --email boss@firm.ru --domain forecast.firm.ru   # на домене с автоматическим HTTPS
./install.sh --demo                # дополнительно создать demo@example.com и загрузить демо-данные
```

Скрипт идемпотентен и ничего не перезаписывает:

1. проверяет Docker и создаёт `infra/.env` (права 600, в git не попадает) с новыми ключами шифрования секретов 2FA (`BACKOFFICE_MFA_KEY` для операторов, `AUTH_MFA_KEY` для пользователей компаний);
2. спрашивает токен Telegram-бота (можно пропустить; также берётся из переменной `TELEGRAM_BOT_TOKEN`) и пишет его только в `infra/.env`;
3. поднимает сервисы через `./run.sh up`;
4. создаёт **оператора платформы** (сервис `backoffice`, страница `/operator`) со случайным паролем (20 символов); пароль передаётся процессу через стандартный ввод, а не аргументом, не окружением и не `.env`;
5. печатает **ссылку на страницу оператора, логин и пароль**. Пароль также лежит в `infra/.operator-credentials` (права 600, в `.gitignore`).

Демо-пользователь со слабым паролем по умолчанию не создаётся.

## Двухфакторная защита оператора (TOTP, обязательна)

- **Первый вход:** логин и пароль → экран с QR-кодом (рисуется на сервере, наружу ничего не отправляется) → код из приложения (Google/Microsoft Authenticator, Яндекс Ключ) → 8 резервных кодов, показываются один раз. Сессии (cookie `op_session`) до подтверждения кодом нет.
- **Дальше:** пароль + 6-значный код. Вместо кода можно ввести резервный, каждый работает один раз.
- **Защита:** код принимается в окне ±1 шаг (30 с) и только один раз; после 5 ошибок билет второго шага сгорает, а оператор блокируется на 5 минут; билет живёт 5 минут. Секрет хранится в БД зашифрованным (ключ `BACKOFFICE_MFA_KEY`, иначе файл `mfa.key` в томе `backoffice-data`), в логи не пишется. Все шаги пишутся в журнал действий оператора.
- **Отключить** требование можно только для локальной отладки: `BACKOFFICE_REQUIRE_2FA=0`.

Для пользователей компаний 2FA необязательна: `AUTH_REQUIRE_2FA=1` в `infra/.env` делает её обязательной для всех, кто входит по паролю. Вход по ЭЦП 2FA не обходит: для учётной записи с включённой или обязательной 2FA сессию по подписи не выдают, нужен вход по паролю и коду. Токены внешнего API 2FA не затрагивает. Заблокированная оператором компания не получает ни билета второго шага, ни сессии после верного кода.

## Сброс 2FA

Оператор потерял телефон и резервные коды:
```
docker compose -f infra/docker-compose.yml exec backoffice python -m backoffice.create_operator --reset-2fa boss@firm.ru
```
Секрет и резервные коды удаляются, сессии завершаются, при следующем входе 2FA настраивается заново. Потерян `BACKOFFICE_MFA_KEY` (или `mfa.key`): сначала сбросить 2FA так же.

Пользователь компании: `docker compose -f infra/docker-compose.yml exec auth python -m auth.cli reset-2fa --email user@firm.ru`.

Ещё одного оператора добавляют так же, как первого: `docker compose -f infra/docker-compose.yml exec backoffice python -m backoffice.create_operator operator2@firm.ru` (пароль спросит интерактивно).

## Проверка

Покрыто тестами: `backend/services/tests/test_backoffice_mfa.py` (первый вход без сессии, повтор кода, резервные коды, лимит попыток, сброс, шифрование секрета, CLI), `test_mfa.py` (векторы RFC 6238 и вход пользователей), `backend/api/src/admin.rs` (билет вместо cookie, cookie только после кода), `backend/api/src/roles_tests.rs` (бан и 2FA). Сам `install.sh` проверен только с подменой `docker` и `curl`; запуск с реальным Docker и вход в браузере в разработке не выполнялись.
