# Установка одной командой и двухфакторная защита оператора

## Установка

Нужен только Docker (Compose v2) и curl.

```
./install.sh                       # локально: http://localhost:3000
./install.sh --email boss@firm.ru --domain forecast.firm.ru   # на домене с автоматическим HTTPS
./install.sh --demo                # дополнительно создать demo@example.com и загрузить демо-данные
```

Скрипт идемпотентен и ничего не перезаписывает:

1. проверяет Docker и создаёт `infra/.env` (права 600, в git не попадает) с новым ключом `AUTH_MFA_KEY`;
2. спрашивает токен Telegram-бота (можно пропустить; также берётся из переменной `TELEGRAM_BOT_TOKEN`) и пишет его только в `infra/.env`;
3. поднимает сервисы через `./run.sh up`;
4. создаёт оператора (владельца компании) со случайным паролем и обязательной 2FA;
5. печатает адрес страницы, логин и пароль. Пароль также лежит в `infra/.operator-credentials` (права 600, в `.gitignore`).

Демо-пользователь со слабым паролем по умолчанию не создаётся.

## Двухфакторная защита (TOTP)

- **Первый вход оператора:** логин и пароль → экран с QR-кодом (рисуется на сервере, наружу ничего не отправляется) → код из приложения (Google/Microsoft Authenticator, Яндекс Ключ) → 8 резервных кодов, показываются один раз.
- **Дальше:** пароль + 6-значный код. Вместо кода можно ввести резервный, каждый работает один раз.
- **Защита:** код принимается в окне ±1 шаг (30 с) и только один раз (повтор того же кода отклоняется); после 5 ошибок билет второго шага сгорает, а пользователь блокируется на 5 минут; билет живёт 5 минут. Секрет TOTP хранится в БД зашифрованным (ключ `AUTH_MFA_KEY`, иначе файл `mfa.key` в томе auth), в логи не пишется.
- **Вход по ЭЦП** не обходит 2FA: для учётной записи с включённой или обязательной 2FA сессию по подписи не выдают, нужен вход по паролю и коду. Токены внешнего API 2FA не затрагивает.
- **Кому обязательна:** оператору, созданному `install.sh`. Чтобы потребовать 2FA от всех, кто входит по паролю: `AUTH_REQUIRE_2FA=1` в `infra/.env`. Остальные пользователи подключить её сами пока не могут.

## Сброс 2FA

Телефон и резервные коды потеряны: на сервере выполнить
```
docker compose -f infra/docker-compose.yml exec auth python -m auth.cli reset-2fa --email boss@firm.ru
```
Секрет и резервные коды удаляются, сессии завершаются, при следующем входе 2FA настраивается заново.
Потерян `AUTH_MFA_KEY` (или `mfa.key`): сначала сбросить 2FA так же.
